# API-09 일시정지와 같은 회차 재개

## 현재 API로 연결한 범위

실행 화면의 작업 메뉴에서 `POST /api/v1/sessions/{sessionId}/commands`에 `pause` 명령을 보냅니다. 서버가 `held`와 `USER_PAUSED`를 반환하면 S10을 엽니다. 연구생 홈의 이어하기도 같은 세션을 다시 조회합니다. S10은 서버가 반환한 절차 버전과 완료한 측정 수, 다음 조건·회차를 표시합니다. 다른 보류 사유는 기존 오류 복구 경로로 보내며, 해당 화면의 Edge 연동은 [API-06](https://github.com/HandsOn-ondevice/HandsOn-Frontend/issues/38)에서 이어집니다.

S11에서 작업자가 실험 조건과 장치 설치 상태를 직접 확인하면 앱에서 `resume` 요청을 보낼 수 있습니다. 현재 서버는 이 요청을 처리하면서 장치·센서 기준을 검사합니다. 실패하면 `423`의 원인을 보여 주고, 성공하면 서버가 반환한 같은 커서로 실행 화면에 복귀합니다. 앱에서 받은 작업자 확인은 현재 세션 리비전에만 적용합니다. 확정된 실패 뒤 다시 요청하려면 재확인이 필요합니다. 응답 유실 시에는 원래 명령의 본문과 멱등 키로 다시 보냅니다.

## 서버팀과 합의할 사항

| 항목                      | 현재 개발 서버 동작                                                                                                                | 확인할 계약                                                                                                              |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 보류 사유와 화면          | 사용자 일시정지는 `USER_PAUSED`를 반환합니다. `resume` 자체는 다른 `held` 사유도 받을 수 있습니다.                                 | `holdReason.code`별로 S10/S11과 API-06 복구 화면 중 어디로 보낼지, 각 화면에서 허용할 명령과 재개 후 새 측정 방식        |
| 세션에 연결된 장치 재점검 | `resume`이 현재 장치·센서 기준을 확인하고 통과하면 바로 실행 상태로 바꿉니다. `GET /sensors/latest`는 현재 센서값을 제공합니다.    | 재개와 분리된 점검이 필요하면 센서 판정과 실패 사유, 세션·커서·보류 기록에 연결할 식별자, 판정의 유효 기한과 무효화 조건 |
| 작업자 확인               | 명령은 작업자 역할과 세션 소유권을 확인합니다. `resume` 명령은 작업자 확인을 전송할 필드가 없으므로 앱에서 확인 여부를 보관합니다. | 확인할 항목과 작업자 권한, 서버가 확인을 기록할 시점과 요청 필드, 확인 내용이 없거나 오래됐을 때의 거절 응답             |

현재 계약은 HandsOn-Backend의 개발 브랜치 `suhhee/feat-simulation-api`에서 확인했습니다. [Edge 개발 서버 계약](https://github.com/HandsOn-ondevice/HandsOn-Backend/blob/ee525993fc45fb15eda4d96b5c14428d60666bc0/docs/api-contract.md#L63-L91) · [API-09 이슈](https://github.com/HandsOn-ondevice/HandsOn-Frontend/issues/41)

## 재현 방법

격리한 HandsOn Edge v0.1.0 시뮬레이션 서버(`ee52599`)의 상태를 테스트 시작 전에 읽고, 별도 SQLite 데이터에 `kit-distance` 승인 절차의 정상 측정 1회를 생성합니다. Playwright Chromium 360×800에서 실제 세션을 열어 작업 메뉴로 일시정지한 뒤 홈으로 나갔다가 같은 세션을 선택합니다. S11에서 확인란을 선택하기 전에는 재개 버튼이 비활성화됩니다.

테스트는 격리 서버에 `POST /api/v1/simulation`으로 `disconnected` 상태를 설정합니다. `resume`이 `423 SENSOR_DISCONNECTED`를 반환하면 S11에 원인이 표시되고 확인란이 해제됩니다. 시뮬레이션을 정상으로 돌린 뒤 확인란을 다시 선택하면 새 리비전으로 요청을 보내고, `200` 응답의 세션 ID와 커서가 일시정지 전과 일치하는지 확인합니다. 세션을 다시 조회해 이전 측정과 완료 이벤트가 유지되고 `sessionResumed` 이벤트가 한 건인지 확인합니다.

Edge를 `127.0.0.1:8043`에서 실행하고 브라우저 Origin으로 `http://localhost:8143`을 허용합니다. 격리 서버의 작업자·숙련자 테스트 토큰을 각각 `HANDSON_E2E_OPERATOR_TOKEN`, `HANDSON_E2E_EXPERT_TOKEN`으로 실행 셸에 설정합니다.

```sh
HANDSON_E2E_EDGE_SESSION=1 EXPO_E2E_PORT=8143 \
  EXPO_PUBLIC_HANDSON_EDGE_BASE_URL=http://127.0.0.1:8043 \
  npm run test:e2e -- e2e/edge-session.spec.ts --grep '일시정지 후'
```

테스트는 격리한 루프백 서버에서만 실행되며, 끝나면 생성한 세션을 취소하고 초기 시뮬레이션 설정을 복원합니다. 실제 Android 기기·Orange Pi·배포 서버의 실행 결과는 이 검증에 포함되지 않습니다.
