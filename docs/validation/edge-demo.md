# 단계 완료·숙련자 결과 재조회와 전체 시연 검증

[이슈 #56](https://github.com/HandsOn-ondevice/HandsOn-Frontend/issues/56)의 장면 1~15를 Playwright Chromium 모바일 뷰포트 412×920에서 재현합니다. 연구생과 숙련자는 독립 브라우저 컨텍스트로 같은 Edge에 접속합니다. Playwright 테스트마다 새 Edge 프로세스와 SQLite 디렉터리를 만들고 종료 시 정리합니다.

## 재실행

[HandsOn Edge 통합 커밋 `f5edd0b`](https://github.com/HandsOn-ondevice/HandsOn-Backend/tree/f5edd0b7fc8345f1e6694c2c10fa6d3402e84b53)를 별도 디렉터리에 체크아웃하고 그 디렉터리에서 `uv sync --locked --no-dev`로 Python 환경을 준비합니다. 프런트 저장소 루트에서 아래 명령을 실행합니다. 토큰은 두 테스트 역할을 구분하기 위한 로컬 값입니다. Edge는 기본적으로 18056번 포트를 쓰며 다른 프로세스와 겹치면 `HANDSON_E2E_DEMO_EDGE_PORT`로 바꿀 수 있습니다. Expo 개발 번들은 `.env.local` 등의 Edge 설정을 실행 명령보다 우선하므로, 해당 설정이 없는 별도 워크트리에서 시연을 실행합니다.

```sh
HANDSON_E2E_EDGE_DEMO=1 EXPO_E2E_PORT=19056 \
  HANDSON_E2E_DEMO_BACKEND_DIR=/absolute/path/to/HandsOn-Backend \
  HANDSON_E2E_OPERATOR_TOKEN=demo-operator HANDSON_E2E_EXPERT_TOKEN=demo-expert \
  npm run test:e2e:ui -- e2e/edge-demo.spec.ts
```

Playwright UI에서 **전체 시연**을 한 번 실행하면 숙련자 승인부터 같은 세션의 결과 재조회까지 진행합니다. **완료·이력**은 기존 승인 절차로 장면 13~15를 확인할 실행을 준비합니다. **조도 미달과 HOLD**는 완료 제안을 낸 뒤 조도가 떨어지는 경우를 별도 세션에서 검증합니다. 각 테스트를 펼치면 단계별 성공·실패와 캡처, Edge 응답의 검증 근거를 볼 수 있습니다. 터미널에서 실행하려면 `test:e2e:ui`를 `test:e2e`로 바꿉니다. 산출물은 `artifacts/playwright/edge-demo/`에 저장됩니다.

고정 전사문과 초안은 #53의 시연 입력을 재사용합니다. 웹에서는 준비된 오디오 파일을 업로드하고 Edge가 별도 입력으로 받은 전사문을 반환합니다. Edge 시뮬레이션 규칙이 인식하는 표현은 ‘완료했어’이므로 시연 입력 어댑터가 ‘현재 단계 완료했어’를 이 규칙에 연결합니다. 조도 입력은 2135 → 900 → 2100 ADC로 바꾸고 거리 입력은 16.7 cm로 유지합니다. 승인·세션 진행·보류·재개·LED 출력·결과 저장과 조회는 Edge가 처리합니다.

## 확인 범위

2026-11-24에 macOS 26.4의 Playwright Chromium 156에서 세 시나리오를 터미널로 실행해 통과했습니다. Playwright UI에서도 **전체 시연**을 한 번 선택해 통과 상태와 장면 15의 실행 기록을 확인했습니다. 같은 Edge에서 기존 승인·준비 시나리오도 통과했습니다.

| 구간                      | 화면과 Edge에서 대조하는 값                                                                                                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 숙련자 승인과 연구생 시작 | 발급된 절차 ID와 승인 버전, 거리 기준 15~25 cm, 조도 하한 1500 ADC를 세션 생성 응답까지 연결합니다. 같은 세션의 장치 점검에서 거리 16.7 cm와 조도 2135 ADC를 확인하고, 실행 전후의 모의 LED OFF → ON을 대조합니다.                                                                                |
| 보류와 복구               | 900 ADC에서 모니터가 같은 회차를 자동 보류하고 LED가 OFF로 전환됩니다. 연구생 홈에서 같은 세션을 다시 열면 보류 사유가 보입니다. 900 ADC에서 명시적 재개 요청이 차단되고 2100 ADC로 바뀐 뒤에도 사용자가 재개할 때까지 보류를 유지합니다. 재개의 점검 결과와 같은 회차 복귀, LED ON을 확인합니다. |
| 단계 완료와 제출          | 완료 제안을 받은 시점에 세션 리비전·커서·유효 회차 수가 유지됩니다. 확인한 시도마다 `measurementAccepted`가 한 번 기록됩니다. 필수 회차가 남으면 실행을 계속하고, 마지막 회차를 확인하면 LED 종료 응답과 최종 검토 화면을 확인합니다. 정리 확인 후 같은 세션의 결과를 제출합니다.                 |
| 조도 미달에서 완료 차단   | 웹의 완료 확인 요청을 실제 Edge에 전달하기 직전에 조도를 900 ADC로 바꿉니다. 명령의 새 센서 검사에서 조도 미달로 거절되거나 자동 보류가 먼저 적용되어 리비전이 충돌하면 같은 결과로 이어집니다. 기존 완료 명령을 보류 상태의 최신 리비전으로 보내도 거절되며, UI에는 보류 사유가 표시됩니다.      |
| 숙련자 재조회             | 처음 열어 둔 숙련자 브라우저에서 목록을 새로고침하고 이번에 제출한 결과를 엽니다. 제출 응답의 결과 ID는 이 Edge에서 세션 ID와 같습니다. 절차명, 승인 버전, 작업자, 장치, 유효 거리값과 측정 시각을 실행 중 응답과 대조합니다.                                                                     |

## 화면에서 확인할 수 없는 항목

숙련자 화면은 제출 정보와 조건별 측정값·측정 시각을 표시합니다. 장치 점검부터 조도 저하·자동 보류·복구·재개·완료까지 이어지는 세션 전체 이력은 현재 화면에 표시되지 않습니다. 검증에서는 같은 결과 응답과 세션 이력의 이벤트 순서를 대조합니다. 최초 거리와 조도는 같은 장치 점검 보고서에 있습니다. 자동 보류 이벤트에는 사유와 보류 ID가 남으며, 900 ADC는 보류 시점의 센서 조회 및 같은 보류에 연결된 실패 재개 점검에서 확인합니다. 2100 ADC는 재개에 성공한 점검의 측정값과 측정 시각으로 확인합니다.

실제 갤럭시 탭 녹음·STT·음성 안내, 물리 센서와 LED는 실기기에서 같은 대본으로 확인해야 합니다.
