## S05 응답 검증

- S05 보고서는 현재 `attemptId`를 되돌려줘야 한다. ID 누락/불일치는 실패다. 기존 Repository 메서드는 변경하지 않았다.
- `startedAt <= report.checkedAt <= completedAt`를 확인한다. 센서 checkedAt과 필수 측정 observedAt은 점검 시작 이전이면 거절한다. 기존 observedAt <= sensor.checkedAt <= report.checkedAt 검사도 유지한다.
- 임의 TTL, 센서 안전 임계값, 실제 장비 timeout은 추가하지 않았다. 오래 걸려도 현재 시도의 유효 응답이면 허용한다.
- 원본은 `DeviceCheckAttempt.report`에 그대로 저장한다. 거절된 원본이 출처를 api라고 주장하더라도 Mock 엔진의 Evidence.source는 mock으로 유지한다. 별도 `validation.sensors`에 유효 여부/표시 상태/오류를 저장하고 카드와 sensor Evidence의 action/diagnosticValidation이 이를 함께 사용한다.
- 잘못된 단위/결측값/시각/중복 센서를 가진 raw passed는 정상 카드나 성공 근거가 되지 않는다. 다른 유효 센서의 개별 정상 결과는 보존하며, 필수 센서 하나라도 실패하면 통신 확인과 실험 시작을 차단한다.
- 재점검 시작 시 기존 통신 확인을 무효화하는 규칙, 작업자 확인 5개, 세션/절차 버전/revision/requestId 규칙과 S06/S07 명시적 완료 절차는 유지한다.

## 실행 경계와 표시

- `WorkflowProvider` 기본 Mock 생성은 `__DEV__`일 때만 허용한다. 배포 환경에서 기본 공급 또는 Mock 직접 주입은 준비 중 안내를 표시한다.
- Mock Repository의 생성/조회/명령/구독도 배포 환경에서 거절한다. 실제 API Repository의 명시적 주입을 금지하지 않는다.
- 미리보기 응답 조건은 일반 화면에서 `더 보기 → 미리보기 설정`으로 이동했다. 2/6 fixture는 진입 화면의 미리보기 설정에서 선택하며 신규 실험은 계속 0/6이다.
- 하단 시트 포털은 feature Context 밖에 렌더링될 수 있으므로 화면에서 제어기를 구해 props로 전달한다. 공통 BottomSheet는 변경하지 않았다.
- `source: mock | api`, 내부 Mock 클래스·시나리오·이벤트는 보존한다. 화면에는 개발 용어 대신 자연스러운 안내를 사용하고, 측정 타일은 합성 출처를 `참고값`으로 표시한다. 점검/측정 정보에는 현재 값이 실측값이 아님을 명시한다.
- 음성 안내 재생이나 실제 녹음이 구현된 것으로 바꾸지 않았다. 안내 버튼은 텍스트 안내를 표시하고, 음성 확인 정보에는 음성 입력/재생 서비스 미연결 상태를 설명한다.

## 남은 위험

- 실제 서버/센서/STT/TTS/AI는 미연결이다. API 조립 및 서버 DTO 검증은 별도 통합 작업이다. 현재 feature 배포 경로는 준비 중 안내이며 실측값을 제공하지 않는다.
- `__DEV__`는 런타임 개발 빌드 구분이다. 개발 빌드를 최종 배포물로 배포하면 합성 점검 성공을 볼 수 있다. 최종 배포물은 release 모드와 실제 API 주입을 검증해야 한다. 이번에는 실제 release/Android 기기 실행을 검증하지 않았다.
- 실제 장치/서버/클라이언트 시계가 다를 수 있다. ID 상관관계를 유지하면서 시작/관측/수신 시각의 권위·동기화·오차 정책을 서버 담당자와 합의해야 한다. 임의 오차 허용값은 넣지 않았다.
- 기존 간헐적 폰트 HTTP 응답 손상의 근본 원인은 미확정이다. 예전 trace에서 HTTP 헤더가 폰트 응답 중간에 삽입된 기록이 있으며, 이 기록은 저장소 폰트 자체 손상을 뜻하지 않는다. RootLayout/폰트/테스트 제한 시간을 바꾸지 않았다. 이번 검증의 오류 원인과 구분해서 기록한다.
- 실제 API 연결 전에 성공 보고서 만료/재연결/취소/영속 복원 정책도 합의해야 한다. 이번 수정은 시도 식별과 인과 순서 검증이며 시간 기반 최신성 정책을 확정하지 않는다.
