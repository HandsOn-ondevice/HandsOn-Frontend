# S02–S03 승인 절차 선택과 준비 입력 검증

2026-11-05 기준. [S02](https://www.figma.com/design/PDVmFhYGwSHs6ZrQmsowek?node-id=2084-414)·[S03](https://www.figma.com/design/PDVmFhYGwSHs6ZrQmsowek?node-id=2084-500)의 첨부 SVG를 기준으로 화면을 구성했다. S02는 S00에서 선택한 작업 환경과 장치를 표시한다. S03의 작업자 자리는 로그인 사용자 정보가 없어 합성 절차의 승인자를 표시한다.

## 실행 경로

1. 신규 연구생과 지능형 임베디드·IoT 센서 연구실을 선택하고, 연구생 홈의 승인된 절차에서 **전체 보기**를 누른다. 하단 **실험** 탭으로도 진입할 수 있다.
2. S02에서 전체·LED·센서 점검·최근 사용 필터를 바꾼다. 절차를 고르기 전에는 **선택한 절차 확인**이 비활성화된다. 필터가 바뀌면 이전 선택을 해제한다.
3. LED 절차를 선택해 S03으로 이동한다. `LED-M03 · 승인 버전 v1.2`와 설명, 예상 소요 시간, 조건·회차, 필요 장비, 핵심 기준, 단계 요약, 주의사항을 확인한다.
4. **이 버전으로 준비 시작**을 누른다. 개발용 준비 입력 화면에서 `demo-led-characteristics`, `v1.2`, 선택한 환경을 확인한다. 뒤로 가면 S03과 S02로 돌아간다.

## 확인한 동작

- Jest는 승인·환경 필터, 초안·승인 취소 절차 제외, 목록·상세의 로딩·빈 상태·실패, 재시도를 확인한다. 상세 조회 또는 준비 재확인이 다른 버전을 반환하면 최신 버전으로 바꾸지 않고 진행을 막는다. 재확인 중 중복 입력과 이전 환경의 늦은 응답도 검증한다.
- Chromium 개발 화면에서 S00→S02→S03→준비 입력 확인과 뒤로 가기를 확인했다. 412×920, 360×800 웹 화면에서 목록과 상세가 가로로 넘치지 않고, 본문 스크롤과 하단 동작을 사용할 수 있음을 확인했다.
- Android 검증은 `Maestro Android` CI의 `.maestro/procedures-android.yaml`에서 수행한다. 승인 카드 필터·선택, 상세, 준비 입력 전달, 시스템 뒤로 가기를 검증하고 `maestro-android` 아티팩트에 화면과 진단을 남긴다. 로컬 Android 에뮬레이터는 실행하지 않았다.

## 실제 연동 전 확인할 계약

`ProcedureRepository`는 프런트엔드 조회 경계다. 현재는 개발 빌드와 `EXPO_PUBLIC_HANDSON_MAESTRO=1` 빌드에서만 합성 목록·상세를 제공한다. 일반 배포에서는 합성 절차를 반환하지 않는다. API 주소·응답 필드·승인 상태는 확정된 서버 계약으로 매핑해야 한다.

S03은 준비를 요청할 때 같은 `procedureId`, `approvedVersion`, `environmentId`로 다시 조회한다. 승인 취소·버전 변경·환경 불일치로 같은 결과를 받을 수 없으면 준비 요청을 보내지 않는다. 통과하면 `PreparationRequest`에 `procedureId`, `approvedVersion`, 선택한 `environment`의 사본을 보관한다. 이 입력은 프런트엔드 검증용이며, 개발용 화면에서 확인할 수 있다.

A의 S04에는 합의된 입력과 세션 식별자가 필요하다. 세션 생성 시점, 시작 시 서버가 승인 버전을 검증하는 방식, 기존 `/researcher-workflow/[sessionId]/preparation` 연결은 미확정이다. 이 작업에서는 실제 API·세션 생성·장치 통신을 수행하지 않는다.
