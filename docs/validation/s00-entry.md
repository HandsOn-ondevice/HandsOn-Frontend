# S00 역할과 작업 환경 검증

2026-11-05에 개발용 합성 환경으로 확인했습니다.

## 재현 절차

1. 앱의 첫 화면에서 역할 또는 연구실을 고르지 않은 상태로 계속 버튼을 확인합니다.
2. 신규 연구생과 연구실을 선택합니다. 작업 유형과 실행 장치가 선택한 연구실에 맞게 표시되는지 확인합니다.
3. 계속을 눌러 연구생 홈에 진입하고, 뒤로 돌아와 선택한 역할과 연구실이 유지되는지 확인합니다.
4. 같은 연구실에서 숙련 연구생으로 바꾸고 숙련자 홈에 진입합니다.
5. 개발 빌드에서 `handson://dev`로 갤러리를 열고, `handson://?component=SensorCard`로 기존 예제 진입을 확인합니다.

## 자동 검사

- Jest에서 역할·환경 선택 누락, 조회 실패, 재시도 로딩, 조회 성공 후 선택값 전달을 확인했습니다.
- Playwright에서 두 홈의 환경 표시, 화면과 브라우저 뒤로 가기, 선택 없이 홈 주소로 접근했을 때의 S00 이동, 개발 갤러리 진입을 확인했습니다.

## Android CI

PR의 `Maestro Android` 워크플로는 GitHub 호스팅 러너에서 Android APK를 빌드하고 에뮬레이터에 설치합니다. 이 APK는 빌드 단계에서만 `EXPO_PUBLIC_HANDSON_MAESTRO=1`을 전달해 합성 환경을 불러옵니다.

Maestro는 신규 연구생·숙련자 홈 진입과 Android 시스템 뒤로 가기 후 역할·연구실 선택 유지를 확인합니다. 실행 결과와 진단 파일은 PR의 Actions에서 볼 수 있습니다.

## 남은 확인

환경·장치 API 계약과 장치의 실제 연결 판정은 후속 연동 범위입니다. 환경 조회 실패와 재시도는 Jest에서 모의 응답으로 재현했습니다.
