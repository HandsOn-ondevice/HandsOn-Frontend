# US-04 장치·거리·조도에 따른 실행 시작 검증

승인 절차를 선택해 준비를 끝낸 뒤 장치·센서 점검에서 첫 실행 회차까지 이어지는 시연 장면 6~9를 확인합니다. 준비 화면의 세션 ID와 승인 버전을 점검 화면에서 대조하고 같은 세션이 실행으로 전환되는지 확인합니다. 조도는 센서 원시값인 ADC로 확인합니다. [이슈 #54](https://github.com/HandsOn-ondevice/HandsOn-Frontend/issues/54)

## 재실행

HandsOn Edge를 시뮬레이션 모드로 `127.0.0.1:18056`에서 실행합니다. 앱이 새 세션을 `workflowVersion: "2.0"`으로 생성하므로 API-10을 지원하는 백엔드 `67716a5`를 사용합니다. 테스트 전용 데이터 디렉터리를 사용하고 CORS에 `http://localhost:19056`을 허용합니다. Edge를 띄울 때 사용한 작업자·숙련자 테스트 토큰을 실행 셸의 `HANDSON_E2E_OPERATOR_TOKEN`, `HANDSON_E2E_EXPERT_TOKEN`에 설정합니다. 승인 버전 비교는 이 테스트 데이터에 새 절차와 승인 버전을 만듭니다. [HandsOn Edge 소스](https://github.com/HandsOn-ondevice/HandsOn-Backend/tree/67716a54ed80ea4f125d8241cf2c672fd73ba741)

```sh
HANDSON_E2E_EDGE_START=1 EXPO_E2E_PORT=19056 \
  EXPO_PUBLIC_HANDSON_EDGE_BASE_URL=http://127.0.0.1:18056 \
  npm run test:e2e:ui -- e2e/edge-execution-start.spec.ts
```

Playwright UI에서 개별 케이스를 선택해 실행할 수 있습니다. 터미널에서 실행할 때는 같은 환경 변수에 `npm run test:e2e -- e2e/edge-execution-start.spec.ts`를 사용합니다. 시뮬레이터 LED 출력은 숙련자 권한의 `GET /api/v1/simulation`이 반환하는 `led`로 확인합니다. 화면 캡처는 `artifacts/playwright/edge-execution-start/test-results/`에 저장됩니다.

macOS에서 Expo 웹을 띄우고 Chromium 156의 모바일 뷰포트 412×920으로 실행했습니다. 라이브 Edge 시나리오 7개가 통과했습니다. 음성 시나리오에서는 해석 응답을 확인한 뒤 실행 명령이 없어 다음 단계의 검증을 건너뛰었습니다.

## 확인할 상태

| 입력                                    | 확인할 동작                                                                                                                                                                        |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 정상 연결, 거리 16.7 cm                 | 세션에 고정한 승인 버전으로 장치 점검을 통과합니다. 시작 전 LED는 `off`입니다. 시작이 수락되면 같은 세션이 `running`으로 전환되고 첫 커서가 표시되며, LED는 `on`이 됩니다.         |
| 정상 연결, 거리 15 cm 또는 25 cm        | 승인 기준의 양쪽 경계를 각각 통과합니다. 같은 세션의 첫 회차와 LED `on`을 확인합니다.                                                                                              |
| 거리 14.9 cm 또는 25.1 cm               | 각 입력에서 거리 기준을 벗어난 사유가 표시됩니다. 실행은 열리지 않고 LED는 `off`입니다.                                                                                            |
| Orange Pi·초음파 연결 실패              | 연결 실패 사유가 표시되고 실행이 차단됩니다. LED는 `off`입니다.                                                                                                                    |
| 같은 조도 2400 ADC, 승인 하한 2400·2401 | 같은 절차에 하한이 다른 승인 버전 두 개를 발행합니다. 세션마다 준비할 때 선택한 버전을 확인합니다. 하한 2400 버전은 실행을 허용하고, 2401 버전은 밝기 기준 미달 사유를 표시합니다. |

차단 케이스에서는 S05 시작 버튼이 비활성화되는지 확인합니다. 같은 세션의 리비전으로 Edge에 시작을 요청해 명령이 거절되고 첫 커서가 생성되지 않으며 LED가 계속 꺼져 있는지도 확인합니다. 정상 S05 화면에서는 초음파 상태와 거리값을 읽습니다. Orange Pi 연결과 조도 센서 상태·원시값은 같은 점검 시도의 Edge 응답에서 확인합니다.

조도 비교에서는 같은 절차의 두 승인 버전을 연구생 홈에서 각각 열었습니다. 세션 생성 응답의 버전과 조도 하한을 대조하고, 각 세션의 S05에서 실제 판정 결과를 확인했습니다. S05에는 수치 하한과 LED 상태가 표시되지 않아 세션과 시뮬레이터 응답으로 확인했습니다.

## 현재 시뮬레이터로 확인할 수 없는 케이스

- 공개 시뮬레이터 설정은 조도 값을 받지 않고 `2400 adc`를 반환합니다. 따라서 시연 기본값 2135 ADC, 조도 1500 ADC와 1499 ADC의 경계, 같은 1500 ADC에서 승인 하한 1500·1600의 판정 차이는 재현할 수 없습니다.
- `disconnected` 설정은 Orange Pi와 초음파 센서 연결에 함께 적용됩니다. 조도 센서는 정상 응답으로 고정됩니다. LED 쓰기 실패 설정은 결과를 `unknown`으로 반환하므로 장치 점검에서 LED 미연결이 표시되고 출력이 `off`인 경우도 해당 설정으로 재현할 수 없습니다.
- S05의 **실험 측정 시작** 버튼은 `startExecution` 명령을 전송합니다. 별도 케이스에서 Edge에 ‘작업 시작해’의 텍스트 해석을 요청해 `clarification`, `command: null`, `executed: false`와 LED `off`를 확인합니다. 현재 응답에서는 이어지는 음성 기반 시작 단계를 건너뜁니다.
- 실제 거리·조도 변화, 마이크 입력 및 음성 인식, 물리 LED 점등은 실장비 리허설에서 확인합니다.
