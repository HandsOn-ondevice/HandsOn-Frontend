# E05 단계별 기준과 오류 규칙 편집 검증

2026-11-23 · Node 24.3.0 · Expo 58.0.26 · Chromium 및 Android Maestro

## 화면과 저장

- Figma 최종 섹션의 [E05](https://www.figma.com/design/PDVmFhYGwSHs6ZrQmsowek?node-id=2087-1596)를 참고했습니다. 센서 수치, 프로그램 계산 기준, 작업자 확인, 오류 대응을 구분합니다. 시안의 수치는 기본값에서 제외했으며 수치를 편집하면 장비 확인 체크를 다시 받습니다.
- 승인 전 초안에는 빈 필드를 저장할 수 있고 기존 미확정 항목은 계속 표시합니다. 숫자 형식, 전압 최솟값과 최댓값의 순서, 음수가 될 수 없는 시간·편차, 반복 횟수의 입력 오류를 표시합니다.
- 선택한 단계 ID에 기준을 저장합니다. 저장 실패 시 편집을 유지하고, 성공한 초안과 단계만 승인 검토 화면으로 전달합니다. E04에서 다시 저장할 때 단계 ID가 같은 기존 기준을 유지합니다.
- 개발용 모의 저장은 웹의 localStorage와 Android의 앱 내부 파일을 사용합니다. 실제 장비에서의 기준 확인, 서버의 단계별 데이터 계약, 승인·배포 연동은 후속 작업입니다.

## 자동화에서 확인하는 흐름

- `npm run test:e2e -- e2e/procedure-draft.spec.ts`는 기본 수치가 비어 있는지, 역전된 전압 범위와 저장 실패가 E05에 표시되는지, 재시도 성공 후 같은 초안과 단계로 E06에 이동하는지 검사합니다. 앱을 다시 열어 수치·규칙·사람 확인·장비 확인이 복원되는지도 확인합니다.
- `.maestro/step-criteria-android.yaml`은 Android 에뮬레이터에서 숫자 키보드와 텍스트 입력, E06 전달, E04에서 같은 단계를 다시 열었을 때 값과 장비 확인 기록이 유지되는지 검사합니다. 실행 결과와 대상 커밋은 PR의 검증란에 기록합니다.
