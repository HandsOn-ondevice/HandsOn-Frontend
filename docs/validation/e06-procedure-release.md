# E06 절차 최종 승인과 버전 배포

E04에서 초안을 임시 저장하고 **최종 승인 검토**를 누르거나 E05에서 단계 기준을 저장하면 E06으로 이동합니다. **미리보기**에서 저장된 준비물, 단계, 기준값과 오류 규칙을 확인합니다. E05에 남은 필수 기준과 장비 확인을 완료한 뒤 E06에서 준비물·장비와 검토 사실을 확인하면 승인·배포할 수 있습니다.

- `.maestro/step-criteria-android.yaml`은 전자회로 실험실에서 E05 기준을 다시 열어 복원한 뒤 E06의 승인 차단, 미리보기, 확인 입력, 모의 배포를 실행합니다. 같은 환경의 E01·S02·S03에서 반환된 `v1.3`을 대조합니다.
- `e2e/procedure-release.spec.ts`는 Chromium에서 배포 저장을 한 번 실패시킨 뒤 승인 상태가 바뀌지 않고 확인 입력이 남는지 확인합니다. 재시도 후 E01·S01·S02·S03에 `v1.3`이 표시되고 기존 세션의 S04 상세에는 `v1.2`가 유지되는지 대조합니다.
- `__tests__/procedure-release.test.ts`는 미확정 기준과 장비, 오래된 초안, 최종 확인 누락 시 거절을 확인합니다. 같은 초안의 반복 요청은 기존 배포 결과를 반환하며 버전과 작업 환경을 정확히 조회하는지 확인합니다.

승인자와 신규 버전은 개발·Maestro용 모의 응답에 고정되어 있습니다. 기존 실험 세션은 생성 시 복사한 절차 스냅샷을 읽습니다. 새 모의 버전은 승인 목록과 상세에서 조회할 수 있으며, 실행 정의는 현재 `demo-led-characteristics`의 `v1.2`에 연결되어 있습니다.

백엔드 작업 브랜치의 승인 API는 서버가 발급한 초안 ID, 숙련자 인증, 초안 revision과 서버가 검증할 실행 정의가 필요합니다. 현재 앱의 로컬 초안과 해당 API의 연결, 실제 장비 검증은 남아 있습니다. [백엔드 연동 계약](https://github.com/HandsOn-ondevice/HandsOn-Backend/pull/6)
